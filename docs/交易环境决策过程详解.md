# 交易环境决策过程详解

> 本文档用通俗的语言解释 GinkgoBrain 的强化学习交易环境是如何工作的。
> 如果你把整个系统想象成一个"虚拟交易员"，那么本文就是这位交易员的工作手册。

---

## 一、整体架构：谁是谁？

```
BaseTradingEnv          ← 基础交易规则（买/卖/持有、资金管理、奖惩机制）
  ├── StockTradingEnv   ← 股票版（自带观察空间归一化）
  │     └── CryptoTradingEnv  ← 加密货币版（继承股票版，默认手续费更低）
  │
  └── CryptoPPOEnv      ← 独立的高性能加密货币版（用于 4 阶段课程训练）
```

项目中实际存在**两套**交易环境：
- **`envs/` 目录下的三层继承体系**：`BaseTradingEnv` → `StockTradingEnv` → `CryptoTradingEnv`，用 DataFrame 存储数据，适合 Notebook 快速实验。
- **`agents/ppo_shared.py` 中的 `CryptoPPOEnv`**：独立实现，用 NumPy 数组存储数据，性能更高，专门为多进程训练设计。

两套环境的**核心决策逻辑完全相同**，下面统一讲解。

## 二、交易员能做什么？（动作空间）

每一根 K 线，交易员只能做三件事中的**一件**：

| 动作编号 | 含义 | 具体执行 |
|---------|------|---------|
| **0** | 🟡 **Hold（持有/观望）** | 什么都不做。如果有持仓就继续拿着，没有就继续空仓 |
| **1** | 🟢 **Buy（全仓买入）** | 用全部可用余额买入，扣除手续费 |
| **2** | 🔴 **Sell（全仓卖出）** | 卖掉全部持仓，换回现金，扣除手续费 |

### 关键规则
- **全仓制**：买就一次性全买，卖就一次性全卖，不支持部分仓位。
- **幂等保护**：如果已经满仓了再发 Buy 指令，不会重复买入；空仓时发 Sell 指令也是无效操作。
- **手续费**：每次实际成交，扣除 `commission` 比例的费用（如 0.1%）。

### 买卖的数学过程

**买入**（action = 1，且余额 > 0）：
```
可购买数量 = 余额 × (1 - 手续费率) ÷ 当前价格
余额归零，持仓增加
```
例：余额 10,000 元，BTC 价格 50,000 元，手续费 0.1%：
```
可买 = 10,000 × 0.999 ÷ 50,000 = 0.19980 BTC
余额 = 0，持仓 = 0.19980 BTC
```

**卖出**（action = 2，且持仓 > 0）：
```
回收金额 = 持仓数量 × 当前价格 × (1 - 手续费率)
持仓归零，余额增加
```

## 三、交易员能看到什么？（观察空间）

交易员的"视野"是一个二维矩阵，形状为 `(window_size, n_features)`。

### 直觉理解

想象一张 Excel 表格：
- **行数** = `window_size`（如 48 行），代表过去 48 根 K 线
- **列数** = 特征数量，包含价格信息 + 技术指标 + 持仓状态

```
时间 ↓        open   high   low   close  volume  ema_9  rsi   ...  仓位比  是否持仓
48根K线前      0.95   0.97   0.94  0.96   0.3     0.95   0.45  ...  0.0    0.0
47根K线前      0.96   0.98   0.95  0.97   0.5     0.96   0.52  ...  0.0    0.0
...
当前K线        1.00   1.02   0.99  1.00   1.0     1.00   0.65  ...  0.8    1.0
```

### 特征列表（基础 16 列 + 2 列持仓状态）

| 分组 | 列名 | 含义 | 归一化方式 |
|-----|------|------|---------|
| **OHLCV** | `open, high, low, close` | K 线四价 | ÷ 当前收盘价 |
| | `volume` | 成交量 | ÷ 窗口内最大成交量 |
| **趋势** | `ema_9, ema_21` | 9/21 周期指数均线 | ÷ 当前收盘价 |
| | `macd, macd_signal` | MACD 及信号线 | ÷ 当前收盘价 |
| **动量** | `rsi` | 相对强弱指数 (0-100) | ÷ 100 |
| | `stoch_k, stoch_d` | 随机指标 (0-100) | ÷ 100 |
| **波动** | `bb_upper, bb_lower` | 布林带上下轨 | ÷ 当前收盘价 |
| | `atr` | 平均真实波幅 | ÷ 当前收盘价 |
| **量能** | `obv` | 能量潮 | 差分后 clip 到 [-1, 1] |
| **持仓** | `pos_ratio` | 持仓占总资产比例 | 原始值 (0~1) |
| | `is_holding` | 是否持有 (0/1) | 原始值 |

### 为什么要归一化？

神经网络对数值范围非常敏感。如果把原始的 BTC 价格 $60,000 和 RSI 值 65 直接放在一起喂给模型，网络会认为价格的"重要性"是 RSI 的 1000 倍，这显然不对。

归一化策略：
- **价格类**：全部除以窗口最后一根 K 线的收盘价。这样所有价格都变成"相对于当前价格的比值"，大约在 0.9 ~ 1.1 之间。
- **百分比类**（RSI、随机指标）：除以 100，映射到 0 ~ 1。
- **成交量**：除以窗口内最大成交量，映射到 0 ~ 1。
- **OBV**：转换为变化率，clip 到 [-1, 1]。

## 四、表现怎么打分？（奖励函数）

**奖励函数是强化学习的灵魂**。它决定了交易员"**目的**：鼓励交易员"想清楚再动手"，避免反复买卖。但设太大会导致交易员完全躺平。

### 4.5 超额收益奖励（P11）

```python
market_return = log(new_price / old_price)          # 市场本身这一步涨跌了多少
excess_return = log_return - market_return           # 我比市场多赚/少赚了多少
reward += excess_return_coef * excess_return
```

这是解决"模型只会跟着 Buy&Hold 走"问题的关键机制。没有这个机制时，空仓永远得到 reward=0，模型无法区分"正确空仓（躲跌）"和"错误空仓（踏空）"。加上之后，模型才真正有了**择时**的动力：

| 我的状态 | 市场走势 | excess_return | 效果 |
|---------|---------|---------------|------|
| 空仓 | 跌了 | 正值（我没亏，市场亏了） | 奖励！正确躲过了下跌 |
| 空仓 | 涨了 | 负值（我没赚，市场赚了） | 惩罚！错过了上涨 |
| 持仓 | 涨了 | 约等于 0（我跟着市场涨） | 中性 |
| 持仓 | 跌了 | 约等于 0（我跟着市场跌） | 中性（但 risk_aversion 会额外惩罚） |

| `excess_return_coef` | 含义 |
|---------------------|------|
| 0 | 不启用，只关注绝对收益 |
| 0.5 | 温和地引导模型关注 alpha |
| 1.0 | 超额收益与绝对收益同等重要 |
| 2.0 | 极度强调跑赢市场（可能导致过度交易） |

## 五、一个完整的回合长什么样？（Episode 生命周期）

```
                  ┌─────────────────────────────────────────────┐
                  │                 reset()                      │
                  │   初始化余额=10000, 持仓=0, 清空交易记录      │
                  │   如果 random_start=True → 随机选择起始位置   │
                  └──────────────────┬──────────────────────────┘
                                     │
                                     ▼
                  ┌──────────────────────────────────────────────┐
        ┌────────│                step(action)                   │◄──────┐
        │        │  1. 读取当前 K 线的收盘价                      │       │
        │        │  2. 执行买入/卖出/持有                         │       │
        │        │  3. 时间前进一步                               │       │
        │        │  4. 用新价格计算资产变化                        │       │
        │        │  5. 计算奖励（收益+alpha-手续费-惯性惩罚）      │       │
        │        │  6. 更新持仓历史                               │       │
        │        │  7. 返回 (观察, 奖励, 是否结束, info)          │       │
        │        └──────────────────────────────────────────────┘       │
        │                                                               │
        │  done=False ──────────────────────────────────────────────────┘
        │
        │  done=True（走到数据末尾）
        ▼
   回合结束，开始下一轮 reset()
```

### 随机起点（P10）

如果启用了 `random_start=True`，每次 reset 不会从数据的第一根 K 线开始，而是从随机的位置开始。

**为什么？** 因为用多进程跑 6 ~ 8 个并行环境时，如果所有环境都从同一个位置开始，它们会看到完全相同的行情，这导致训练数据的多样性大打折扣。随机起点让每个环境走的是"不同的路"。

## 六、参数调优快速参考

下面这张表概括了各参数对交易员行为的影响方向：

| 参数 | 调大 → 交易员变得 | 调小 → 交易员变得 |
|------|-----------------|-----------------|
| `commission` | 厌恶交易 | 愿意频繁交易 |
| `trade_penalty_coef` | 更少交易 | 更活跃 |
| `action_inertia_coef` | 死拿不动，拒绝翻转 | 灵活进出 |
| `risk_aversion_coef` | 极度保守，不敢持仓 | 敢于承受波动 |
| `excess_return_coef` | 极度追求 alpha，积极择时 | 更关注绝对收益 |
| `gamma`（训练参数） | 看得更远 | 短视近利 |
| `ent_coef`（训练参数） | 更多探索 | 快速收敛（可能陷入局部最优） |
| `window_size` | 参考更多历史 | 反应更快但信息少 |

### 常见"病症"与调参对策

| 症状 | 可能原因 | 对策 |
|------|---------|------|
| 🏳️ 全程空仓不交易 | inertia 或 risk_aversion 过大 | 降低至 0.001 / 0.1 以下 |
| 📊 资金曲线紧贴 Buy&Hold | excess_return_coef 为 0 | 设为 0.5~1.0 引导择时 |
| 📉 跟不上大趋势 | gamma 太小（半衰期太短） | 提高到 0.995 或 0.999 |
| 🔄 疯狂买卖（刷单） | 惩罚系数太小 | 提高 trade_penalty_coef |
| 💀 每次都亏一点点 | commission 设置远高于实际 | 对齐真实费率（如 0.001） |
| 🎲 行为随机、不稳定 | ent_coef 太大或训练不够 | 降低 ent_coef 或增加 timesteps |�量"翻倍 |
| 2.0 | 一次交易的惩罚感 = 三倍手续费 |

**目的**：防止模型学成"高频刷单"。

### 4.4 动作惯性惩罚（P5）

```python
if 当前持仓状态 ≠ 上一步持仓状态:
    reward -= action_inertia_coef
```

每当持仓从"空仓 → 持仓"或"持仓 → 空仓"发生翻转时，扣一笔固定惩罚。

| `action_inertia_coef` | 效果 |
|----------------------|------|
| 0 | 自由进出，没有任何翻转成本 |
| 0.0005 | 轻微摩擦，几乎不影响决策 |
| 0.01 | 严重摩擦，等同于每次翻转凭空亏 1% |

**目的**：鼓励交易员"想清楚再动手"，避免反复买卖。但设太大会导致交易员完全躺平。
